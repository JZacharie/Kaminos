# Blocks design language and contract

Quality bar: a polished SaaS ops dashboard a customer accepts as v1 (Linear, Vercel, Datadog): calm surfaces, one accent, crisp 1 px borders, dense but airy, numbers that line up. If your block looks out of place next to `gallery/kpi.html`, it is not done.

## Tokens (in `blocks.css`; never hard-code a colour, size or space)
- **Surfaces**: `--k-bg` page, `--k-surface` card, `--k-surface-2` inset/hover/header row, `--k-surface-3` pressed/skeleton. Borders `--k-line` (default), `--k-line-strong` (inputs, hover).
- **Text**: `--k-text` primary, `--k-text-2` secondary (labels, units), `--k-text-3` tertiary (ticks, hints). All AA (>= 4.5:1) on bg, surface and surface-2 in every theme.
- **Accent**: `--k-accent`, `--k-on-accent`, `--k-accent-soft`. One per page. Use for the primary action, the selected item, links, focus. Never for data series or status. Chosen with the accent presets (see "Accent presets" below); no preset = the theme's own accent.
- **Status**: `ok, warn, crit, info, neutral`. Each has `--k-<s>` (solid: dots, edges, lines), `--k-<s>-bg` + `--k-<s>-t` (pill tint + AA text). Use classes `k-s-<kind>` (they set `--k-s`, `--k-s-bg`, `--k-s-t`) and `h.status(kind)`; app words map through `h.statusKind` ("Delayed", "At risk" -> warn, "Blocked", "High" -> crit). Status colour only on pills, dots, edges and threshold lines; never fill a whole card.
- **Categorical**: `--k-cat-1..8` (Okabe-Ito based, colour-blind safe, light and dark variants). Use `h.cat(i)` or `h.catFor(key)` (same key = same colour in every block on the page), and draw the legend swatch with the same value. The colour of a key never depends on render order (see "Stable category colours"). Fills with text on them: `color-mix(in srgb, var(--k-cat-N) 16%, var(--k-surface))` plus a 3 px solid edge of the colour; text stays `--k-text`.
- **Type** (system font; `.k-b` sets tabular numerals): `--k-fs-xs` 11 px ticks, `-sm` 12 labels/pills/table header, `-md` 13 table body, `-base` 14 body, `-lg` 16 card title, `-xl` 20, `-2xl` 26; KPI value 28. Weights 500/600/700.
- **Space** 4-pt: `--k-1` 4, `--k-2` 8, `--k-3` 12, `--k-4` 16, `--k-5` 20, `--k-6` 24, `--k-8` 32, `--k-10` 40. Card padding `--k-pad` (16), gaps `--k-gap` (16), table row `--k-row` (36). `data-k-density="compact"` on `<html>` = 12/12/32.
- **Radius**: `--k-r-sm` 4 (chips, inner), `--k-r` 8 (buttons, inputs, states), `--k-r-lg` 12 (cards), `--k-r-pill`.
- **Elevation**: `--k-e1` cards (barely there), `--k-e2` hover, popovers. Borders do the work, not shadows.
- **Focus**: `box-shadow: var(--k-focus)` (2 px surface gap + 2 px accent ring) on every interactive element. The ring is the accent, so every preset keeps it at 3:1 or more on surface, bg and surface-2.

## Themes: one attribute on `<html>`
`data-k-theme="ops"` (default: light ops console, blue), `"control"` (dark control room, teal, always dark), `"warm"` (cream and terracotta brand). Each is a product of its own, not a recolour:
- **ops**: cool greys, cobalt accent, 4/8/12 radius, sans titles, solid hairline grids. Categorical: cobalt, teal, violet, rose, ochre, sky, clay, slate.
- **control**: blue-black canvas, luminous teal accent with a glow focus ring, 3/5/8 radius, no shadows, UPPERCASE tracked panel titles over a hairline rule, small-caps KPI labels. Categorical: sky, aqua, lavender, orchid, wheat, ice, rosewood, steel.
- **warm**: paper canvas, cream cards, ink text, terracotta accent, crimson (not orange) for crit, serif titles and KPI figures (`--k-font-title`, `--k-font-num`), 6/10/16 radius, soft warm shadows, dotted chart grids. Categorical: indigo, deep teal, plum, rose, ochre, dusty sky, clay, umber.
Each 8-step palette keeps every step apart from the others and from ok/warn/crit/info under normal, protan, deutan and tritan vision (OKLab distance, Machado 2009), with marks at 3:1 on the light surfaces and 4.5:1 on the dark ones. Theme-aware tokens a block may read: `--k-grid`, `--k-grid-dash` (chart gridlines; `.k-b-grid` uses both), `--k-axis` (axis baseline), `--k-map-sea`, `--k-map-land`, `--k-map-coast`, `--k-font-title`, `--k-font-num`, `--k-title-*`. `ops` and `warm` also have dark variants that follow `color-scheme` (system `prefers-color-scheme`, or kit `data-theme="light|dark"`), so the scorer's dark pass stays readable. Switch with `K.theme.set(name)`: it sets the attribute and dispatches `k-theme` on `document`. Draw SVG colours as `var(--k-...)` (in `fill`/`stroke` style or attributes) so they follow the theme with no re-render; only canvas or computed colours need `theme: true` in the definition (core re-renders on `k-theme`). With a block theme set, `blocks.css` maps the kit's variables (`--accent`, `--surface`, `--line`, `--ok`...) to the tokens, so `kit.css` components match.

## Accent presets: `data-k-accent` on `<html>`
`data-k-accent="blue|green|teal|gold|indigo|violet|rose|orange"` replaces the accent of whatever theme is active (ops light or dark, warm light or dark, control). No attribute = the theme's own accent (ops cobalt, control teal, warm terracotta); `blue` is the ops cobalt on any theme. It sets `--k-accent`, `--k-on-accent`, `--k-accent-soft` (the accent mixed into the theme's own surface: 10 % light, 16 % dark) and, through them, the focus ring, the primary button, pressed chips, links and the kit's own `--accent`.
- **How an app sets it**: `head.json` `{"accent": "green"}`. ui-build writes `data-accent` (kit.css components) and, when blocks are used, `data-k-accent` (blocks). At run time: `K.theme.accent('green')` (returns the current preset; `''` or `null` goes back to the theme's accent; `K.theme.accents` lists the names).
- **Contrast** (computed from the rendered CSS for 8 accents x ops light/dark x warm light/dark x control + the theme defaults, in `tests/blocks/core.test.mjs`): accent as text >= 4.5:1 on surface, bg, surface-2 and the soft tint; on-accent text on the accent and on the hovered button >= 4.5:1; focus ring >= 3:1 on surface, bg and surface-2. A new preset must pass that test.
- **Categories are not accents**: `--k-cat-N` stay per theme. Pick the accent for the brand, and keep series colours for data. When the accent hue equals the colour of the first category (green accent + a green category), prefer `K.block.palette` to move that category.

## Stable category colours
`h.catFor(key)` returns the same `var(--k-cat-N)` for the same key on every screen, in any render order (hidden routes render when first visited). Resolution, first match wins:
1. A slot given with `K.block.palette({ 'Stage A': 0, 'Stage B': 1 })` or `K.block.palette(['Stage A', 'Stage B'])` (position = slot, 8 slots, always wins; call it once at page level, before or after the blocks).
2. A block config `colorKeys: ['Stage A', 'Stage B', ...]` (any block): the same ordered domain, filled in when the block draws. It only fills keys that have no slot yet; a different slot for a key that already has one is kept and warned once.
3. A fixed hash of the key (FNV-1a modulo 8): stable, but two keys can share a slot (the 8 slots cannot be hashed apart for every set). Names you compare side by side (stages, depots, vehicle types) belong in a palette or `colorKeys`.
Legends, markers, bars and lanes call `catFor` with the same key, so they stay equal. Use `h.cat(i)` only when you pick the index yourself.

## Heading level
`headingLevel` defaults to 2 since core 1.2: an app screen has one `h1` (the screen title), so a framed block's own title is the next level, `h2`; sections inside a block (board columns, detail sections) use `headingLevel + 1`. Pass `headingLevel: 3` (up to 6) when the block sits inside a section that already has an `h2`; values under 2 are raised to 2 (the page title is never taken). Blocks without a title print no heading, so nothing is skipped.

## Block contract
- **Files**: `addon/kit/blocks/<name>.js` + `<name>.css`, gallery `addon/tests/blocks/gallery/<name>.html`. Load order: `blocks.css`, `<name>.css`, `core.js`, `<name>.js`. Pure: no network, no globals besides `K`, no `document.write`, no timers left behind.
- **Define**: `K.block.define('name', { version, schema, render(el, cfg, h), empty?(cfg), emptyText?, frame?, resize?, theme? })`. Names are lower-case `[a-z0-9]`. Callers use `K.block.name(elOrSelector, cfg)` -> handle `{el, ok, cfg, update(partial), destroy()}`. `update` merges top-level fields and re-renders.
- **Schema** (light): `field: {type: 'text'|'time'|'string'|'number'|'boolean'|'array'|'object'|'function'|'any', required?, default?, enum?, of? (item schema for arrays of objects)}`. `text` = string or number; `time` = the same, for fields that hold a time or date (steps `planned`/`actual`, feed `time`/`at`, lanes and series time windows). A valid JS `Date` is accepted in every `text` and `time` field and in table cells: it is shown through `h.when(date)` (clock time `14:30` when it is on the page's day, else `12 Nov, 14:30`; locale from `<html lang>`, 24 h; table columns of type time/date/datetime use `h.time/h.date/h.datetime`), and a `time` field also keeps the instant as `<field>$ms` for sorting. An invalid Date shows `—` and warns once. Unknown fields are ignored. Core validates, applies defaults (on copies: caller data is never mutated) and passes the clean `cfg`.
- **Never throws**: bad config, an exception in `render`, or a resize re-render all end in an inline `.k-block-error` inside `el` ("This <name> block cannot be shown" + what is wrong) and ONE `console.warn('[K.block] <name>: ...')` per block+message. Never `console.error`: the scorer counts it as a JS error. A missing element warns once and returns a no-op handle (`ok: false`).
- **Failure-proof contract: hard errors only for structure, soft errors for optional item fields.** Hard (the `.k-block-error` card): config is not an object, a required field is missing or has the wrong type, a top-level field has the wrong type or enum value, an array item is not an object. Soft: a wrong type or enum value in an OPTIONAL field of an array item (`steps[0].sub` is an object, a `width` that is a string) does not take the block down. The block renders, the field shows `—` (text and time fields) or is treated as missing (other types), the block root gets `data-k-soft="<n>"` and the console gets ONE warning per path pattern (`steps[0].sub must be a string or number, got object; shown as "—" (the rest of the block is shown)`; `[3]` and `[7]` count as the same pattern). Old and new bad-config galleries keep their hard-error cases because those are required or top-level problems.
- **Poison text guard**: text a block renders that holds `undefined`, `NaN`, `null` (whole word, exact case) or `[object Object]` is a sign of broken app glue. It stays visible (an app bug must not be hidden), its element gets `data-k-suspect` and the console gets ONE `[K.block] suspect text in <block>: "..."` per block and text. Core checks after the first render and again after later DOM changes (table sort and pages, feed "Show more"); config error cards are skipped because they name the bad value on purpose. **For a quality gate: count `[data-k-suspect]` (broken app data), `.k-block-error` (a block that could not draw) and `[data-k-soft]` (a block that drew with a bad optional field) per route; any of them is an issue.**
- **Two ways to mount**. Imperative: `K.block.table('#a-ship', cfg)` from `data.js`. Declarative, for static screen HTML: `<div data-k-block="table" data-k-cfg="shipments"></div>` plus `window.UI_BLOCKS = {shipments: {...}}` (or `shipments: function (CANON, el) { return {...}; }`) in `data.js`. Core runs `K.block.mount()` on DOMContentLoaded; call `K.block.mount(rootEl)` again after adding HTML. It mounts each element once (idempotent); a missing key or an unknown block becomes an inline error naming it. A measuring block (`resize: true`) inside a hidden route (`display:none`, width 0) waits and renders when the route is shown (ResizeObserver, `hashchange`, `kit:route`), so it always draws at its real width. `K.block.mount(name, el, cfg)` still works.
- **Frame**: by default core wraps the block as a card (`.k-b-card`) with an optional header (`title`, `subtitle`, `actions`). `frame:false` in the definition or the config renders bare (KPI tiles are their own cards; or embed inside an app card).
- **States**: `cfg.state = 'loading'|'empty'|'error'`, or `def.empty(cfg)` true -> core draws the state (`h.empty/loading/error`), sized to content (min 88 px), never a stretched blank card. `compact: true` in the config or the definition (or a block under 320 px wide) draws a one-row state (36 px) for toolbars and switches; helpers take `{compact: true}` as last argument. Errors are a quiet card with a crit left edge in every theme. Framed title and subtitle wrap to 2 lines (then clamp), ids and times in them never split.
- **Resize**: `resize: true` re-renders on container width change (debounced, >= 2 px). SVG blocks measure `el.clientWidth` and draw at 1:1 pixels (viewBox = real px), so text never scales with width. Extra listeners: `h.resizeObserver(node, fn)` and `h.cleanup(fn)`; destroy and re-render clean them.
- **Helpers** `h` (see `core.js`): `esc el svg line nowrap rich num time date datetime when measureText font fitLabels niceTicks thin uid status statusKind cat catFor token empty loading error warn rerender fit fitStop padFit fade` (+ `h.fill`); page level: `K.block.palette(map|keys)`, `K.theme.set(name)`, `K.theme.accent(name)`. Locale from `<html lang>`, 24 h. `h.nowrap(text)` returns nodes with times, time ranges, ids, codes and amounts in `.k-b-nw` spans ("21:15-22:40", "AL-320", "EUR 95", "102 kW"); `h.rich(text, {max})` keeps every word with a digit, colon, slash or hyphen whole ("Hapag-Lloyd", "door 23") and ellipsises one longer than `max` (18). Both go straight into `h.el(tag, attrs, h.rich(v))`. `niceTicks` always ends at or above the max. `statusKind` also maps cancelled, hold/on hold, overdue, offline, rejected -> crit; paused, waiting, degraded -> warn; will be ready, scheduled, planned, charging, in transit, en route -> info; completed, arrived, resolved, confirmed -> ok (case, `-` and `_` ignored).
- **Data honesty**: a block shows the numbers it is given. It never recomputes, rounds differently or re-derives an ETA. If it shows a total, it shows `cfg.total` and warns once when it differs from the sum.
- **Accessibility**: real elements (`a`, `button`, `table`), visible focus, `title` on every truncated text, a static SVG has `role="img"` + `aria-label`, status never by colour alone (dot + word). **An SVG with focusable parts is `role="group"` + `aria-label`, never `role="img"`** (the map: an img's children are presentational, so focusable markers inside it are nested interactive controls, axe `nested-interactive`). Control rows are not columns: a button's label and value share one inner element, a chip group may wrap (`flex-wrap:wrap`), so the gate's `narrow-row` rule (3+ flex children under 96 px each) does not read them as a squeezed table.

## Layout rules every block follows
1. Ids, times, numbers, codes and short names never break: `white-space:nowrap` (`.k-b-nw`, `.k-b-num`) or one line with ellipsis + `title`: build it with `h.line(text)` (a `.k-b-line` clip box with the text in an inner span; a bare `.k-b-line` with direct text is flagged `overlaps` by the scanner). Never `overflow-wrap:anywhere`, `word-break:break-all` or `hyphens:auto`.
2. Blocks size to their content. No `height:100%`, no stretched grid cells, no empty run over 160 px inside a card. Fixed heights only for charts and maps, from config. The one exception is row-height fill (below), which is opt-in and only ever uses height another card already created.
3. Every SVG label is measured (`h.measureText`) and then fits, is thinned (`h.thin`), moves (`h.fitLabels`), or is dropped with the value still in a `title`. First and last axis ticks are anchored inside the plot (`text-anchor` start/end), so nothing is clipped at the edge.
4. No horizontal page overflow at 1024-1920. Wide content (tables, long timelines) scrolls inside its own card with the first column sticky.
5. A card under 480 px wide has at most 3 columns of key/value or table cells; below that it stacks.
6. Axis text is 11 px `--k-text-3`, gridlines 1 px `--k-line`, plots have 8-12 px inner padding. Integer data gets integer ticks.
7. Marker, bar, lane and legend colours come from the same token for the same key (`h.catFor`).
8. A "now" or limit line is drawn behind text with a label in the axis band; it never crosses a label.
9. Spacing and type only from tokens; one accent; status colour only for status.

## Row-height fill: a short card next to a tall one (`fill`, `k-row-fill`)
Default: a card is as tall as its content, so a short card in a `k-grid` row ends early (the white void under "Delays by cause" beside "Alert feed"). Two opt-ins, both leave the default alone:
- `fill: true` on a block, or class `k-row-fill` on the grid (every block directly in it; wrapper divs like `.k-span-6 > #a-x` are fine; `fill: false` opts one block out). The frame stretches to the row height and the block **uses** the height: rows are added first (feed `limit`, table `pageSize` grow while they fit), then every row gets extra padding (`--k-fill-pad`, 0 to 24-28 px per side). The card never makes the row taller than the other cards made it; if it is the tallest, nothing changes.
- `fill: 'scroll'`: the other cards set the row height (minimum `--k-fill-min`, 16 rem), the body scrolls inside with a bottom fade, a tab stop and `role=region`. Use it for long lists beside a short card.
Only blocks that declare `fill: true` in `K.block.define` take part (feed, detail, table; board and bars follow Z-viz); `fill` on another block logs one `console.warn` and is ignored. Bad values (`fill: 'yes'`) show the inline config error.

How a block opts in (3 lines):
1. `K.block.define(name, {fill: true, ...})`.
2. In `render`, when `h.fill === 'grow'`, call `h.fit(spec | [spec, ...])`, `spec = {base, max, set(n)}`: `set(n)` lays the block out at step n (rows shown, plot px...), steps must grow the block monotonically. Core runs it after render, finds the largest n per spec (bisect) that keeps `el.offsetHeight` at the row height, and runs it again when the card's height changes (a neighbour rendered, resize). Reusable spec: `h.padFit(node, max)` sets `--k-fill-pad` on node, which the block adds to its row padding: `padding-block: calc(var(--k-3) + var(--k-fill-pad,0px))`. A control that expands content by hand (Show more) calls `h.fitStop()`.
3. For `'scroll'` core scrolls the block body (`.k-b-fill-body`, fade via `h.fade(node)`); a block with its own scroller (table) adds `k-b-own-scroll` to the body and calls `h.fade(scroller)`.
Tests: `tests/blocks/fill.test.mjs`; gallery `tests/blocks/gallery/fill.html`.
